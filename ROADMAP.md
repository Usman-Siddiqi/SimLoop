# Roadmap

Milestones are ordered by dependency. Each has acceptance criteria that must
be met (and tested) before it is considered done. Tick boxes as criteria are
met; `docs/PROGRESS.md` has the session-by-session log.

## M0: Project foundation
- [x] `CLAUDE.md` with the hard rule, authorship rule and conventions
- [x] Roadmap, progress log and findings log in the repo
- [x] Packaging (`pyproject.toml`, `src/` layout, `py.typed`), MIT license
- [x] Ruff, mypy `--strict` and pytest configured; GitHub Actions CI on 3.11 to 3.13

## M1: Deterministic core loop
- [x] `SimEventLoop`: a from-scratch `asyncio.AbstractEventLoop` with a virtual
      clock; unimplemented I/O fails closed
- [x] Sleeping and timeouts take no wall-clock time (an hour of simulated time
      runs in well under a second)
- [x] Standard asyncio works unchanged: tasks, gather, wait, wait_for,
      timeout, TaskGroup, Queue, Lock, Event, Semaphore, Condition,
      cancellation, async generators, `to_thread`/`run_in_executor`
- [x] Seeded `ChoiceSource` is the only source of framework randomness and
      records every draw
- [x] Pluggable scheduling policies: faithful FIFO and seeded random
      (origin-preserving); timer jitter as a sound timing perturbation
- [x] Same seed produces an identical trace digest, in-process and across
      processes with different `PYTHONHASHSEED`
- [x] Deadlock detection: the run fails with the list of blocked tasks when
      nothing can make progress
- [x] Step and simulated-time limits to catch livelocks

## M2: Leak detection and sandboxing
- [x] `time.*`, `random` module state, `os.urandom` and `uuid4` are
      virtualized during a run and restored afterwards
- [x] Real sockets, DNS, threads and subprocesses inside a simulation raise
      `NondeterminismError`
- [x] Blocking `time.sleep` advances simulated time and is recorded in the trace
- [x] `datetime.now()` / `date.today()` virtualized
- [x] Optional determinism self-check: rerun a seed and compare digests,
      reporting the first divergent trace event (`simloop check`,
      `check_determinism`, and automatically in `explore`)

## M3: Properties, search and reporting
- [x] `always(...)` invariants checked after every step, `eventually(...)`
      properties checked at a deadline or at the end of a run
- [x] Unhandled exceptions in background tasks and callbacks fail the run
- [x] `explore()` runs many seeds and groups failures by signature
- [x] CLI: `simloop run` / `simloop explore` on a `module:function` target
- [x] Parallel exploration across processes (`workers=`, `-j`), with
      reports identical to a sequential run
- [x] pytest plugin: `@simloop.test(seeds=...)` / marker, failing seed shown
      in the test report, `--simloop-seed` to reproduce (plus an example
      database that replays remembered failures first)

## M4: Simulated network
- [x] Named nodes with their own address; `asyncio.open_connection` /
      `start_server` work over the simulated network
- [x] Configurable per-link latency distribution, drops, duplication and
      reordering (datagram API), all seeded
- [x] Partitions (symmetric and asymmetric) that can be scheduled and healed
- [x] Simulated DNS (`getaddrinfo`)
- [x] Determinism tests for every network feature

## M5: Fault injection
- [x] Node crash and restart (tasks of a node cancelled; node restarted from
      its entry point; in-memory state lost, "disk" state kept)
- [x] Slow operations and I/O errors (`ConnectionResetError`, timeouts) at
      seeded points
- [x] Fault plans: declarative schedules (`faults.schedule` with `at`,
      `during`, `between`, `every`, random ranges and targets) plus seeded
      random nemesis tasks
- [x] Faults appear in the trace and text timeline (HTML timeline: M7)

## M6: Minimization
- [x] Replay a run exactly from its recorded choice sequence
- [x] Shrink a failing choice sequence (chunk deletion, value lowering toward
      zero = FIFO / no fault / minimum latency) while it still fails with the
      same signature
- [x] Output a minimized reproduction (seed + choice file) and its trace

## M7: Debuggability
- [x] Readable text timeline of a run
- [x] HTML timeline (per-task lanes, network messages, faults) generated
      from a real trace
- [x] Seed-exploration summary image and an animated GIF of a simulated execution
- [x] README visuals generated by scripts in `scripts/` (timeline, seed grid, GIF)

## M8: Scheduling search improvements
- [x] PCT-style priority scheduling (bounded number of priority change points)
- [x] Feasibility confirmation: failures found under a non-FIFO scheduler
      are searched for with asyncio's order plus timer jitter
- [ ] Coverage-guided or novelty-guided seed exploration (optional)

## M9: Real-world validation
- [ ] Harnesses for popular async libraries (done so far: aiojobs,
      async-lru, redis-py asyncio, aiorwlock, aiolimiter, aiocache, aiohttp,
      httpx/httpcore, websockets, anyio, uvicorn + Starlette, aiotools,
      aiometer, asyncstdlib, cashews, aiostream, aiomisc, tenacity, backoff, singleflight,
      aiodataloader, strawberry-graphql DataLoader, aiomcache, coredis, psycopg-pool, aio-pika, aiologic,
      asyncpg, nats-py, circuitbreaker, aiocircuitbreaker, aiobreaker,
      purgatory, aiocron, APScheduler, CPython asyncio primitives) (candidates: `aiokafka`-style
      clients, aiomysql)
- [x] Each harness documented, runnable as a script, and in CI (small seed budget)
- [ ] `docs/FINDINGS.md` populated with confirmed bugs, suspected issues and
      false positives, each with a reproduction script and seed (16 confirmed, 3 suspected,
      2 false positives, 17 clean harnesses so far)
- [x] README findings section lists only confirmed results
